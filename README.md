# ピアノ練習カレンダー

現在の機能・デザインをそのまま、GitHubでコード管理するためのソース一式です。
`index.html` が編集可能な完全なソースです。HTML・CSS・JavaScriptがすべて含まれ、生成済みの圧縮コードではありません。外部ライブラリ、画像、外部フォント、APIキー、サーバー側のデータベースは使いません。
元の `index.html` は変更していません。バックアップ・復元はアプリ画面と独立した移行用スクリプトです。

## 最初に：練習記録をバックアップする

**起動方法やURLを変える前に [記録のバックアップ・復元](docs/DATA-MIGRATION.md) を実行してください。**
このZIPに、あなたの保存済み練習記録は含まれていません。記録は各端末のブラウザ内にあり、ソースファイルからは取得できません。元のアプリや保存先は削除していません。

## フォルダ構成

```text
piano-calendar-source/
├── index.html                 # アプリの全ソース
├── package.json               # 起動・確認コマンドと依存関係
├── package-lock.json          # 依存関係を固定する管理ファイル

├── AGENTS.md                  # Codex向けの作業方針
├── README.md
├── docs/
│   └── DATA-MIGRATION.md       # 記録のバックアップ・復元
├── scripts/
│   ├── serve.mjs              # Mac用のローカルサーバー
│   └── check.mjs              # 自動動作確認
└── tools/
    ├── backup-records.js      # ブラウザで記録を書き出す
    └── restore-records.js     # ブラウザへ記録を戻す
```

## Macでセットアップ・起動

### A. ファイルを開くだけ（インストール不要）

1. ZIPをダブルクリックして展開します。
2. フォルダ内の `index.html` をSafariやChromeで開きます。
3. 日付を押し、1行1項目で入力して「保存する」を押します。

**以前のHTMLとは別のファイルパスになるため、記録が同じように見えるとは限りません。先にバックアップしてください。**

### B. 今後の開発におすすめの起動方法

1. [Node.js公式サイト](https://nodejs.org/)からLTS版（長く保守される版、22以上）をMacにインストールします。
2. 「ターミナル」を開き、次の文字と半角スペースを入力します。

   ```sh
   cd 
   ```

   続けて展開した `piano-calendar-source` フォルダをターミナルへドラッグし、Returnを押します。`cd` は作業するフォルダを移動する命令です。
3. 以下を順に実行します。

   ```sh
   node --version
   npm --version
   npm start
   ```

4. ブラウザで **http://127.0.0.1:8080** を開きます。
5. 停止するときはターミナルで **Control+C** を押します。再開は同じフォルダで `npm start`。

`npm` はNode.jsに付属する管理ツールです。依存ライブラリは0件なので `npm install` は不要です。管理ファイルを使った確認のため `npm ci` を実行しても構いません。
起動用サーバーはアプリだけを配信し、READMEやバックアップファイルを配信しません。
これはMac自身から開くためのサーバーで、外出先やスマホからはアクセスできません。
8080番が使用中なら、以前のサーバーを停止してください。URLのポート番号を変えると保存領域も変わります。

## 動作確認

ターミナルをもう1つ開き、同じフォルダへ移動して実行します。

```sh
npm test
```

JavaScriptの構文、2026年の祝日・休日18日、2019～2021年の特例、初回サンプル、削除後の再起動、保存不可の場合、バックアップ・復元処理を、模擬データで確認します。あなたのブラウザの練習記録には触れません。

ブラウザでは、バックアップ後に次を確認してください。

- 日付を開いて入力・保存・編集でき、再読み込み後も残る。
- 空欄保存はメッセージが出る。
- 削除は2回押す必要があり、再読み込みしても復活しない。
- 2026年10月12日と9月22日が赤く表示される。
- PCは練習内容が折り返されて全部表示される。
- 幅599px以下ではリストが初期表示で、「月間」で記録の点が出る。
- ダークモード・今日の丸・月移動・入力画面を確認する。

自動テストは画面の見た目や実際のiPhone操作を保証するものではありません。確認用の入力は不要になったらその日だけ削除してください。
祝日の計算範囲は1980～2099年で、将来の祝日法変更があればコードの更新が必要です。

## GitHubへ登録する（GitHub Desktopを使う）

Gitは変更履歴を残す仕組み、GitHubはそのコードをインターネット上に保管するサービスです。
今回は準備のみで、このZIPにはGitの履歴や登録先は含めていません。

1. [GitHub](https://github.com/)のアカウントを作成・確認します。
2. [GitHub Desktop](https://desktop.github.com/)をインストールしてGitHubにログインします。
3. GitHub Desktopで **File → Add Local Repository** を選び、展開した `piano-calendar-source` フォルダを指定します。
4. Gitの管理対象でないという案内が出たら **create a repository here** を選びます。作成先が、`index.html` の入ったフォルダ自身になっていることを確認します。README・Git ignore・Licenseは追加生成せず、同梱のものを使います。
5. **Changes** で `index.html`、`.gitignore`、README等があることを確認します。個人のバックアップJSONや秘密情報があれば、公開前に対象から外してください。
6. まだ未保存の変更がある場合は、Summaryに `Initial piano calendar source` と入れ、**Commit to main**（初回の変更履歴を保存）を押します。作成時に初回コミット済みなら不要です。
7. **Publish repository** を押します。名前は例えば `piano-calendar`、**Keep this code private** にチェックを入れて登録します。
8. **View on GitHub** でフォルダ構成と各ファイルを確認します。ZIPそのものだけをアップロードするのではなく、展開したファイル一式を登録してください。

バックアップJSONはプロジェクト外へ保管するのが確実です。`.gitignore` は未登録のファイルを除外するもので、すでに登録した個人データを履歴から消す機能はありません。
公式手順: https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-an-existing-project-to-github-using-github-desktop

## Codexで修正してGitHubへ反映する

### MacのCodexアプリから作業する

1. Codexでローカルのプロジェクト／フォルダを開く操作を選び、GitHub Desktopに登録した **同じフォルダ** を開きます。表示名はアプリのバージョンによって異なる場合があります。
2. そのプロジェクト内で、新しいチャットを開始します。この準備に使ったチャットだけを続けるのではなく、実際のGit管理フォルダを作業対象にします。
3. 例えば次のように依頼します。

   > READMEとAGENTS.mdを読んでください。保存形式と現在のデザインを維持し、○○だけを修正して、npm testで確認してください。まだコミット・pushはしないでください。

4. ブラウザで `npm start` の画面を確認します。
5. GitHub Desktopの **Changes** で差分（変更前後の違い）を確認し、Summaryを書いて **Commit to main**、続けて **Push origin**（GitHubへ送信）を押します。
6. 次の作業前に **Fetch origin / Pull origin** でGitHub側の変更を取り込みます。

Codexにコミット・pushまで頼む場合は、その範囲を明示してください。ローカル作業では、フォルダへのアクセスとGitHubへ送信できる認証が必要です。GitHub Desktopから送信する運用なら、ターミナル用の認証設定を急いで用意する必要はありません。
公式: https://learn.chatgpt.com/docs/app

### Codexのクラウド環境を使う場合（任意）

Macのローカルプロジェクトだけで上の運用は可能です。外出先等からクラウドで修正する場合は、CodexのCloud環境を作成し、GitHubを接続して、このリポジトリへのアクセスを許可します。対象リポジトリを選択し、環境の準備とテスト結果を確認して環境を公開し、タスクを開始します。環境の公開はアプリのWeb公開とは別です。
セットアップで追加ライブラリのインストールは不要です。確認コマンドは `npm test`、Node.jsは22以上を指定します。変更はプルリクエスト（変更案）として確認してからmainに取り込み、MacではPullします。
利用可能な画面やクラウド機能はアカウント・プラン・組織設定に従います。
公式: https://learn.chatgpt.com/docs/cloud

## GitHub管理とスマホ用Web公開は別

GitHubへコードを登録するだけでは、スマホでアプリを開くURLにはなりません。今までの公開先を使い続けるなら、その公開先の `index.html` を更新します。将来GitHub Pagesなどに移す場合は、先に記録をバックアップし、新しい公開先で復元してください。
この準備ではサイトの公開、既存公開先の変更、GitHubアカウントへの登録は行っていません。

## 保存データについて

保存先は **現在使っている端末・ブラウザのlocalStorage**、キーは `piano-practice-v1` です。初回済みの印と、日付ごとの練習内容をまとめて保存します。
同じブラウザ・同じオリジン（通信方式、ホスト名、ポート番号の組合せ）なら通常は同じ記録が使えます。`file://` はファイルごとの扱いがブラウザ依存です。詳細と移行手順は [DATA-MIGRATION.md](docs/DATA-MIGRATION.md) を参照してください。
GitHubはコードの保存先であり、練習記録の自動バックアップ・同期先にはなりません。
